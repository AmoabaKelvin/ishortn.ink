The iShortn REST API lets you create short links from your own code, list them, change where they point, delete them and pull their click analytics. Every endpoint lives under one base URL and speaks JSON. API access is part of the **Pro** and **Ultra** plans; see [API access by plan](#api-access-by-plan).

```text
https://ishortn.ink/api/v1
```

| Endpoint | What it does |
| --- | --- |
| [`POST /api/v1/links`](/docs/api/create-link) | Create a short link |
| [`GET /api/v1/links`](/docs/api/list-links) | List your short links, newest first |
| [`GET /api/v1/links/{alias}`](/docs/api/get-link) | Get a short link |
| [`PATCH /api/v1/links/{alias}`](/docs/api/update-link) | Change a link's destination, alias, expiry or schedule |
| [`DELETE /api/v1/links/{alias}`](/docs/api/delete-link) | Delete a short link |
| [`GET /api/v1/analytics/{alias}`](/docs/api/link-analytics) | Get click analytics for a link |
| [`GET /api/v1/me`](/docs/api/get-me) | Get the account that owns the key, to check a connection |
| [`POST /api/v1/clicks/verify`](/docs/api/verify-click) | Confirm a verified click (called by iShortn's redirect page) |

To shorten links and check their clicks without writing code, use the [Raycast extension](/docs/integrations/raycast) or the [n8n nodes](/docs/integrations/n8n), which run on this API. For a walkthrough with curl examples, and how the Bitly, Dub, Short.io and Rebrandly APIs differ, read the [URL shortener API guide](/blog/url-shortener-api-guide).

## Authentication

Every request except [Verify a click](/docs/api/verify-click) needs an API key in the `x-api-key` header.

```bash
curl https://ishortn.ink/api/v1/links/launch-day \
  -H "x-api-key: YOUR_API_KEY"
```

To create a key (Pro or Ultra only):

1. Open [Settings](/dashboard/settings#api-keys) in the dashboard and scroll to **API Keys**.
2. Click **Create API Key**.
3. Copy the key from the dialog and store it somewhere safe, such as your secret manager or an environment variable.

The key is shown once. iShortn stores only a SHA-256 hash of it, so a lost key can't be recovered: delete it in Settings and create a new one. Treat the key like a password. Anyone who has it can create, change and delete links on your account, so never put it in client-side code or a public repository.

A missing, unknown or deleted key returns `401` with the code `unauthorized` and the message `Invalid or missing API key`. Keys on accounts that are suspended or deleted stop working the same way.

## API access by plan

API keys need a **Pro** or **Ultra** plan. Free accounts can't create keys: Settings shows **API access is a Pro feature** with an upgrade button in place of **Create API Key**. [Compare plans and upgrade](/pricing) to use the API.

Keys on an account without a paid plan stop working after a notice period:

- **Keys created on Free before API access became Pro-only** keep working, on Free [rate limits](#rate-limits), until a single cutoff seven days after the notice email about the change.
- **Keys on an account whose paid plan ended** keep working on Free limits until 7 days after the end of the paid period, or until the Free cutoff above if that is later. A cancelled plan counts as paid until the end of the period you paid for, and a `past_due` subscription keeps full Pro or Ultra access while payment is retried.

During the notice period every response carries these headers, and JSON object responses get an extra `warning` field, next to the usual fields, that names the cutoff:

| Header | Value |
| --- | --- |
| `Deprecation` | `@` followed by a Unix time (seconds) seven days before the `Sunset` time ([RFC 9745](https://www.rfc-editor.org/rfc/rfc9745)) |
| `Sunset` | The time the key stops working, as an HTTP date such as `Sat, 28 Nov 2026 14:00:00 GMT` ([RFC 8594](https://www.rfc-editor.org/rfc/rfc8594)) |
| `Link` | `<https://ishortn.ink/pricing>; rel="sunset"` |

```json
{
  "warning": "API access requires a Pro or Ultra plan. This API key stops working on November 28, 2026 at 2:00 PM UTC. Upgrade at https://ishortn.ink/pricing to keep using the API."
}
```

The account's email address also gets a notice when the period starts and a reminder 24 hours before the cutoff. [Settings](/dashboard/settings#api-keys) shows the cutoff under your key.

After the cutoff, every request with the key returns `403` and this JSON body, whatever the endpoint. It is the one error that doesn't use the [standard error shape](#responses-and-errors): `error` is a string, not an object.

```json
{
  "error": "API access requires Pro",
  "upgrade_url": "https://ishortn.ink/pricing"
}
```

Keys aren't deleted. [Upgrading to Pro or Ultra](/pricing) makes the same keys work again straight away, with your new plan's limits.

## Which links the API can reach

A key works in one workspace:

- A **personal key** (created in your personal workspace) works in your **personal workspace**. Links created with it are added there, and listing, `GET`, `PATCH`, `DELETE` and analytics requests only find links there. Links in a [team workspace](/docs/teams) return `404`.
- A **team key** (created by a team owner or admin under [Team API Keys](/docs/teams#api-access)) works in that **team workspace**, on the team's Ultra plan. Links created with it belong to the team, and requests only find the team's links. Personal links, including those of the member who created the key, and other teams' links return `404`.

[`GET /api/v1/me`](/docs/api/get-me) returns the key's `workspace`, so a tool can tell which one it's connected to.

## Domains

A short link is identified by its alias **and** its domain: `isht.app/launch-day` and `isht.ink/launch-day` are different links. Each endpoint that takes an alias also accepts a `domain`:

- When you leave `domain` out, the API uses the **default domain** from [Settings → General](/dashboard/settings#general) (for a team key, the team's default domain). If none is picked, it uses `isht.app`.
- You can pass any [platform domain](/docs/platform-domains) (`isht.app`, `isht.ink`, `ishortn.ink`) or a [custom domain](/docs/custom-domains) that is **active** in the key's workspace.
- Any other domain returns `403` with the code `forbidden` and the message `Domain not available for this API key`.

Domains are matched case-insensitively and a trailing dot is ignored.

## Plans and limits

Requests are checked against the plan of the key's owner, exactly as in the dashboard; team keys use the team's Ultra plan. The Free column applies only to keys in their [notice period](#api-access-by-plan):

| Rule | Free | Pro | Ultra |
| --- | --- | --- | --- |
| New links per month (API and dashboard combined) | <PlanValue plan="free" cap="linksLimit" /> | <PlanValue plan="pro" cap="linksLimit" /> | <PlanValue plan="ultra" cap="linksLimit" /> |
| Shortest custom alias | 6 characters | 1 character | 1 character |
| Password protection | No | Yes | Yes |
| Scheduled activation (`activatesAt`) | No | Yes | Yes |
| UTM parameters (`utmParams`) | No | No | Yes |

The monthly link count resets on the first day of each calendar month. See [Plans and limits](/docs/plans) for everything else.

## Rate limits

Requests are limited per account, not per key: all of your API keys share one budget. Both windows apply, and each is a sliding window.

<ApiRateLimits />

Every response carries the current state of the window closest to its limit:

| Header | Meaning |
| --- | --- |
| `X-RateLimit-Limit` | Requests allowed in that window. |
| `X-RateLimit-Remaining` | Requests left in that window. |
| `X-RateLimit-Reset` | Unix time (seconds) when that window rolls over. |

A request over the limit returns `429` with a `Retry-After` header (seconds), the code `rate_limited` and the message `Rate limit exceeded. Retry in N seconds.` Rejected requests don't count against the limit. Wait for `Retry-After` before retrying, and retry other failures with a backoff.

## Responses and errors

Successful responses are JSON with `Content-Type: application/json`. Dates are ISO 8601 strings in UTC, or `null` when unset.

Error responses are JSON with an HTTP status code and an `error` object:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Request body is invalid",
    "details": [
      {
        "path": "url",
        "message": "Enter a valid URL, e.g. https://example.com"
      }
    ]
  }
}
```

| Field | Type | Description |
| --- | --- | --- |
| `code` | string | A stable, machine-readable code from the table below. Branch on this, not on the message. |
| `message` | string | A human-readable message you can show to your users, for example `Link not found`. |
| `details` | array | One `{ "path", "message" }` entry per invalid field for `validation_failed`, where `path` is the field's location joined with dots, such as `utmParams.utm_source`. An empty array for every other code. |

The one exception to this shape is the [plan-gated `403`](#api-access-by-plan) after a key's notice period, whose body is `{"error": "API access requires Pro", "upgrade_url": "https://ishortn.ink/pricing"}`. [Verify a click](/docs/api/verify-click), which takes no API key, is outside this scheme and answers bad requests with an empty `400`.

| Code | Status | Meaning |
| --- | --- | --- |
| `bad_request` | `400` | The request is invalid, for example an alias in the wrong format or a URL that failed the [link safety check](#link-safety). |
| `invalid_json` | `400` | The request body isn't valid JSON. The message is `Request body must be valid JSON`. |
| `validation_failed` | `400` | The body or query string doesn't match the endpoint's schema. The message is `Request body is invalid`, or `Query parameters are invalid` for [List links](/docs/api/list-links), and `details` lists the fields. |
| `unauthorized` | `401` | Missing or invalid API key. |
| `forbidden` | `403` | The domain isn't available to the key, the feature or domain isn't on your plan, the monthly link limit is reached, or the account is restricted. |
| `not_found` | `404` | No link with that alias on that domain in the key's workspace. |
| `conflict` | `409` | The alias is already taken on that domain. |
| `rate_limited` | `429` | Rate limit exceeded. See [Rate limits](#rate-limits). |
| `internal_error` | `500` | Something went wrong on our side. Retry later. |

| Status | Meaning |
| --- | --- |
| `200` | Success |
| `201` | Link created |
| `202` | Accepted (Verify a click) |
| `204` | Link deleted (no body) |
| `400` | The request is invalid. `bad_request`, `invalid_json` or `validation_failed`. |
| `401` | Missing or invalid API key |
| `403` | Domain not available, a plan-only feature, the monthly link limit, or a restricted account (`forbidden`). The key's account isn't on Pro or Ultra and its notice period has ended (`{"error": "API access requires Pro", "upgrade_url": "https://ishortn.ink/pricing"}`). |
| `404` | No link with that alias on that domain in the key's workspace |
| `409` | The alias is already taken on that domain |
| `429` | Rate limit exceeded. See [Rate limits](#rate-limits). |
| `500` | Something went wrong on our side. Retry later. |

## Link safety

Every destination URL is checked before a link is created or its destination changes. A URL that fails the check is rejected with `400`, the code `bad_request` and one of the messages listed in [Abuse and acceptable use](/docs/abuse#link-safety-checks).
