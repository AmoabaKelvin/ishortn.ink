---
title: CSV bulk import
description: Create many short links at once from a CSV file or a Bitly link export. File format, columns, limits and error messages.
---

Bulk import creates one short link per row of a CSV file. It's available on **Pro and Ultra** and in team workspaces.

## Upload a file

1. Open the [dashboard](/dashboard).
2. Open the **…** (bulk actions) menu next to **New Link** and choose **Upload CSV**.
3. Drop in your `.csv` file, or click to choose it.
4. Click **Import links** and wait for the summary, which reads like `48 links created, 2 failed, 3 skipped (deleted in Bitly)`.

## File format

The first row must be a header row. Column names match in any case; other columns are ignored, so you can upload an export from another tool without trimming it.

| Column | Required | Description |
| --- | --- | --- |
| `url` | Yes | The destination URL. |
| `alias` | No | A custom alias. Follows the [alias rules](/docs/short-links#aliases). Leave empty for a generated alias. |
| `domain` | No | A [platform domain](/docs/platform-domains) or an active [custom domain](/docs/custom-domains) in the workspace. Defaults to `isht.app`. |
| `title` | No | The link's name, shown in the dashboard. A `name` column works too. |
| `note` | No | A private note on the link. |

```csv title="links.csv"
url,alias,domain,note
https://example.com/spring-sale,spring-sale,isht.app,Instagram bio
https://example.com/blog/launch-day,,isht.ink,
https://example.com/pricing,pricing-2026,,Newsletter footer
```

## Import a Bitly export

Upload a link export from Bitly as it is: the file Bitly gives you from **Links** → **Export**. Both the current export (`Link`, `Custom Link`, `Destination URL` columns) and the older one (`Bitlink`, `Custom Bitlink`, `Long URL`) work.

- Each row's custom back-half (or Bitly's code, when the row has none) becomes the alias, the title becomes the link name, and the note records the original Bitly link.
- Rows marked `Deleted` are skipped and don't count toward your limit.
- **Branded domains:** connect the domain in [Domains](/docs/custom-domains) and wait until it shows **Active** before importing. Links on it keep their exact address, so printed links and QR codes keep working once the domain's DNS points to iShortn. Rows on a domain that isn't connected fail with `<domain> isn't connected to this workspace.`
- **Original codes:** with **Also keep Bitly's original codes working** checked (it's checked automatically when the file is a Bitly export), a custom link like `go.example.com/spring-menu` also gets its Bitly code, such as `go.example.com/3XCetqn`, as a second link to the same destination. Each code counts as one link (on Pro, from the custom-domain import allowance below while it lasts), and codes only take allowance left after every row's own link.
- **bit.ly links** can't move: `bit.ly`, `j.mp` and `bitly.is` belong to Bitly. These rows are created on your default domain, keeping the custom back-half when it's free, and the summary lists the new address for each.

Importing the same file again is safe: links created by an earlier run are counted as already imported, so after fixing a domain you can re-upload the whole file.

For the whole move, including pointing your domain's DNS away from Bitly, see [Move your links from Bitly](/docs/migrate-from-bitly).

## Limits

- Each created row counts toward your [monthly link limit](/docs/short-links#monthly-link-limit), except rows that use the custom-domain import allowance below. If you've already reached it (and have no import allowance left), the whole upload is rejected. Otherwise rows are created in file order until the limit is reached, and the remaining rows fail with `Monthly limit of {limit} links reached. Upgrade your plan to create more.`
- On Pro, rows on one of the workspace's active [custom domains](/docs/custom-domains) use a one-time import allowance of 5,000 links instead of the monthly limit, so you can move a branded domain from another shortener in one go. The allowance doesn't reset; once it's used up, those rows count toward the monthly limit like any other. The summary says how many rows used it and how many are left. Rows on platform domains always count toward the monthly limit.
- Every destination goes through the [link safety check](/docs/abuse#link-safety-checks).

## Row errors

A row that fails doesn't stop the others. The summary lists each failed row with the reason:

| Message | Fix |
| --- | --- |
| `Missing url` | Put a full URL, including `https://`, in the `url` column. |
| `Enter a valid URL, e.g. https://example.com` | Put a full URL, including `https://`, in the `url` column. |
| `Alias can be at most 20 characters` | Shorten the alias. |
| `Alias is used by an earlier row in this file` | Give each row a different alias. |
| `Alias already exists` | Pick another alias, or leave it empty. |
| `Alias can only contain alphanumeric characters, dashes, and underscores` | Remove other characters from the alias. |
| `Selected domain is not available for this workspace.` | Use a platform domain or one of the workspace's active custom domains. |
| `<domain> isn't connected to this workspace.` | Bitly exports: add the domain in Domains, wait until it shows Active, then import the file again. |
| `… links stay on Bitly … Created <short link>.` (a notice, not a failure) | None needed. Use the new short link listed. |
| A link safety message | The destination was flagged; see [Abuse and acceptable use](/docs/abuse). |
