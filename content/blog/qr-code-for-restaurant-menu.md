Menus change all the time. Prices go up, a supplier runs out, the summer specials end. If the QR code on your tables points at last month's PDF, you either reprint every table card or live with a menu that's wrong.

This guide covers how to set up a restaurant menu QR code so that never happens: where to host the menu, whether you need a static or dynamic code, how to print it, and how to change the menu later without touching the tables.

## The short version

1. Put your menu online at a link that opens well on a phone.
2. If that link will **never** change, a free static QR code is fine.
3. If the link might change (new PDF each season, a new ordering platform, a different file for lunch), use a **dynamic** QR code so you can repoint it without reprinting.
4. Print it big enough, test it on real tables, and keep a few paper menus for guests who'd rather not scan.

## Step 1: Put your menu online

A QR code doesn't hold your menu. It holds a link. So the first job is to give the menu a home. You have four common options:

| Where the menu lives | Good for | Watch out for |
|---|---|---|
| **A page on your own website** | Fast to load, easy to read, good for Google | Someone has to update the page |
| **A PDF** (Google Drive, Dropbox, your site) | Quick if your menu already exists as a design file | PDFs are often hard to read on a phone. Drive links need "Anyone with the link" access |
| **Your ordering or delivery platform** | Guests can order from the table | Platform fees, and the link changes if you switch platforms |
| **A menu builder tool** | Nice layouts with no design work | Some lock the menu or QR code behind a subscription |

Whatever you pick, open the link on your own phone over mobile data, not Wi-Fi, before you go further. If you have to pinch and zoom to read the prices, guests will too.

**PDF tips if you go that route:** export one menu section per page, use a large font, and keep the file small (under about 2 MB) so it loads on a weak signal.

## Step 2: Static or dynamic QR code?

This is the decision that matters most.

**A static QR code** encodes your menu link directly in the pattern. It works forever, needs no account and costs nothing. But it can never change, and it can't count scans. If the link it contains stops working, the code is dead.

**A dynamic QR code** encodes a short link. The short link forwards to your menu. Because the forwarding happens on a server, you can change where it goes at any time, and every scan gets counted. The downside is that it depends on the provider: if they shut the short link off, the code stops working. That's how a lot of "expired" menu codes happen. Some generators disable codes when a free trial ends. (More on that in [why QR codes stop working](/blog/qr-code-stopped-working).)

So which one?

- **Static is fine** when your menu is a page on your own website at a fixed address (yourcafe.com/menu) and you update the page itself. The link never changes, so the code never needs to.
- **Dynamic is the better choice** when your menu is a file whose link changes when you upload a new version (most Google Drive and Dropbox setups), when you might switch ordering platforms, or when you want to know how many people actually scan.

## Step 4: Print it so it scans

Most menu-code problems are printing problems. Before you order 40 table cards:

- **Size.** On a table card read from about 30 to 40 cm away, make the code at least 3 to 4 cm wide. Bigger is safer, especially in dim light.
- **Quiet zone.** Leave a clear margin around the code. Don't let a border, pattern or text touch it.
- **Finish.** Glossy laminate reflects overhead lights straight into the camera. Matte laminate scans more reliably.
- **Words.** Add a line like "Scan for our menu" or "Menu and today's specials". A bare square on a table gets ignored, or mistaken for a payment code.
- **Wi-Fi.** If mobile signal is poor inside, print the guest Wi-Fi details on the same card.
- **Test the real thing.** Print one card, put it on a table at night with the lights you actually use, and scan it with an iPhone and an Android phone.

Keep a few paper menus too. Some guests don't have a phone with them, some have a flat battery, and some just prefer paper. A QR menu works best as the default option, not the only one.

3. Save. The next guest who scans the same printed card gets the new menu.

Test it with your phone straight away. If you're using Google Drive, check the new file's sharing setting is "Anyone with the link". A private file is the most common reason an updated menu shows a sign-in screen.

A few ways restaurants use this:

- **Seasonal menus.** Swap the PDF four times a year; the table cards stay the same.
- **Special events.** Point the code at a set menu for Christmas week, then switch back.
- **Temporary closures or changes.** If the kitchen is closed for a day, point the code at a short notice page.
- **Switching platforms.** If you move from one ordering platform to another, update the link once and you're done.

## Step 6: See which codes get scanned

Every scan of a dynamic code is counted, so you can answer questions that used to be guesswork:

- **How many tables actually use the QR menu?** If scans are low, guests may be asking for paper menus, or the code may be hard to spot.
- **When do people scan?** Scans over time show your busy periods.
- **Which placement works?** Use separate codes for separate places: one for tables, one for the front window ("See our menu"), one on takeaway bags ("Order again"). Five free codes are enough for most cafes.

## Common questions

### What is a dynamic QR code for a restaurant menu?

It's a QR code that contains a short link instead of your menu's address. The short link forwards guests to the menu, so you can point it at a new menu at any time and the printed table cards keep working. Every scan is counted.

### Can I change a QR code after it's printed?

Only if it's dynamic. A static code's link is fixed in the pattern. If your printed code is static and the link inside it still works, keep that link working. If the link is dead, you'll need to reprint, ideally with a dynamic code this time.

### How big should a menu QR code be on a table card?

At least 3 to 4 cm wide for a card read from 30 to 40 cm away, and bigger in dim light. Download the print PDF at the size you need, or the SVG, so the code stays sharp.

### Can one QR code show different menus for lunch, dinner and drinks?

The simplest way is a single menu page that links to each menu, with the QR code pointing at that page. If you'd rather have separate codes, make one per menu and label each card clearly.
